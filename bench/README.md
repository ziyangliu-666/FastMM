# Benchmarks

Intel Xeon Platinum 8488C, AWS c7i.xlarge (2 cores, 4 threads), Ubuntu 24.04, Linux 7.0, gcc 13.3, preset `release-native`, pinned to CPU 1, 15 repetitions. Generated by `scripts/bench.sh` on 2026-09-29.

## Hot path

Time per operation. p50 and p99 come from a per-operation `rdtsc` histogram where the benchmark keeps one; otherwise p50 is the median over repetitions of the mean time per operation.

| Stage | Operation | p50 | p99 | p99.9 | Benchmark |
|---|---|---:|---:|---:|---|
| Market data | Binance book ticker, JSON decode | 116.6 ns |  |  | `BM_Json_BinanceBookTicker` |
|  | Nasdaq ITCH message into the L2 book | 81.9 ns | 90.1 ns |  | `BM_ItchL2Bridge_Message` |
|  | L2 book, apply a 20-level delta | 353.3 ns |  |  | `BM_L2_ApplyDelta/20` |
| Engine | Tick to order, simulator | 159.0 ns | 199.0 ns | 319.0 ns | `BM_TickToOrder_Sim` |
|  | Strategy: two quotes (`basic_mm`) | 11.2 ns |  |  | `BM_BasicMM_ComputeQuotes` |
|  | Quote diff against resting orders | 49.4 ns |  |  | `BM_QuoteManager_Reconcile_6Orders1Change` |
|  | Pre-trade risk check | 6.7 ns |  |  | `BM_Risk_CheckNew_Pass` |
|  | OMS: submit an order | 30.9 ns |  |  | `BM_Oms_Submit` |
|  | Journal: record a 128-byte event | 5.7 ns |  |  | `BM_Journal_Record/128` |
| Orders | Binance `order.place`, HMAC-signed | 714.6 ns |  |  | `BM_Encode_BinanceOrderPlace` |
|  | Binance `order.place`, Ed25519 session | 268.2 ns |  |  | `BM_Encode_BinanceOrderPlace_Session` |
|  | OUCH 5.0 Enter Order | 17.4 ns | 19.5 ns |  | `BM_Ouch50_EncodeNewIds` |

Tick to order is one book update through `Engine::step()`: the L2 book, the strategy, the quote diff, risk, the OMS and the two orders serialised into the simulator's outbound queue. The network, TLS and the venue are outside it. Every benchmark: [full-results.md](full-results.md).

## End to end over veth

`fastmm-sim-itch` sends ITCH over MoldUDP64 multicast to `fastmm-live` in another network namespace; `basic_mm` answers with OUCH 5.0 orders over TCP. Preset `release`, kernel receive, `spin_mode = "busy"`, `configs/nasdaq-itch-sim.toml`, on the machine above: simulator on CPU 0, engine on CPU 1, network thread on CPU 3 (the engine core's second hyperthread). Three runs of 30 s on 2026-09-29; each cell is the range over the runs.

| Interval | samples per run | p50 | p99 | p99.9 |
|---|---:|---:|---:|---:|
| Wire to wire: market data sent to order received | 206 to 337 | 11.3 to 11.8 µs | 19.5 to 23.6 µs | 21.3 to 33.2 µs |
| Kernel receive to T0 (network thread) | 138k to 139k | 2.3 µs | 5.4 to 5.6 µs | 14.8 to 32.8 µs |
| T0 to T5: engine, tick to order in the ring | 129 to 191 | 2.6 to 2.7 µs | 12.8 to 14.3 µs | 14.4 to 18.3 µs |
| T0 to the order's `write` returning | 210 to 337 | 7.7 to 8.1 µs | 15.4 to 19.6 µs | 20.0 to 21.7 µs |

With about 300 samples a run, p99.9 is the largest sample. On veth the order's `write` runs the simulator's TCP receive path inside the system call, which is most of the gap between T5 and wire to wire.

## Method

[Benchmarks](../docs/explanation/benchmarks.md) says what each benchmark times and how the results are pooled.

```bash
./scripts/bench.sh --preset release-native --cpu 1 --rounds 3
scripts/bench-e2e.sh --duration 30 --runs 3 --sim-cpu 0 --engine-cpu 1 --net-cpu 3
python3 tools/check_budgets.py bench/results/latest
python3 tools/bench_compare.py bench/results/baseline bench/results/latest
```
